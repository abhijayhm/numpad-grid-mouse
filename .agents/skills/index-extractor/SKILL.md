# Index Extractor

Produce a portable, repo-local project index so any new Cursor IDE reaches the same understanding level without prior chat history.

## Output location

All artifacts live under `docs/indexing/`:

| File | Purpose |
|------|---------|
| `manifest.md` | Table of contents, generation metadata, read order |
| `full-indexing-001.md`, `002.md`, … | Sharded index parts (see size limits) |

Do not put generated index content outside `docs/indexing/`.

## When to run

- `docs/indexing/manifest.md` or any `full-indexing-*.md` is missing
- User requests indexing / re-indexing
- Large structural change (new packages, moved modules, new automation)
- `manifest.md` `generated` date is older than the latest substantive repo change

## Source material (merge all available)

Collect from every source that exists; skip gracefully when absent.

### Local (repository)

1. **Tree** — full file tree; note purpose of top-level dirs and key files
2. **Entry points** — `README*`, `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, Makefiles, CI configs, `bin/`, `scripts/`
3. **Cursor config** — `.cursor/rules/rule-router.mdc`, `.cursor/custom-rules/*.mdc`, `.cursor/skills/**/SKILL.md`, hooks, `AGENTS.md`
4. **Docs** — `docs/**` (excluding stale generated index unless refreshing)
5. **Graphify** — if `graphify-out/graph.json` exists: `graphify query`, `graphify path`, `graphify explain` for architecture, dependencies, and cross-file relationships
6. **Git** — recent commits (`git log -20 --oneline`), branch model, remotes

### Cloud / session (agent context)

7. **Agent transcripts** — scan `agent-transcripts/*.jsonl` when the environment exposes them; extract durable decisions, unresolved TODOs, and domain facts not yet in repo docs
8. **Prior index** — read existing `full-indexing-*.md` and carry forward still-valid sections; mark superseded content
9. **Cloud agent notes** — any `.cursor/` cloud-synced or session memory the environment provides; fold unique facts into the index

Deduplicate across sources. Prefer repository truth over chat when they conflict; note conflicts in `manifest.md`.

## Sharding rules

- Target **≤ 400 lines** or **≤ 12 KB** per `full-indexing-<NNN>.md` file (zero-padded: `001`, `002`, …)
- One coherent slice per file (e.g. overview, backend, frontend, infra, conventions)
- Delete obsolete shards after re-index; renumber only if gaps would confuse — prefer fresh sequential set
- Never split mid-section across files

## Per-shard template

```markdown
# Full Index — Part NNN: <slice title>

> Generated by index-extractor. Repo truth wins over chat context.

## Scope
[What this shard covers]

## Summary
[3–8 bullets: what a new agent must know from this slice]

## Detail
[Structured sections: components, paths, dependencies, flows, conventions, gotchas]

## Key paths
| Path | Role |
|------|------|

## Cross-references
- Related shards: full-indexing-00X.md
- Source files: `path/to/file`
```

## manifest.md template

```markdown
# Project Index Manifest

| Field | Value |
|-------|-------|
| generated | YYYY-MM-DD |
| generator | index-extractor skill |
| parts | N |
| repo | <root folder name> |

## Read order
1. [full-indexing-001.md](./full-indexing-001.md) — <one-line summary>
2. …

## Quick orientation
[5–10 bullets: purpose, stack, layout, how to run, where rules/skills live]

## Sources used
- [x] local tree
- [x] cursor rules/skills
- [ ] graphify graph
- [ ] agent transcripts
- [ ] prior index

## Staleness
Re-run index-extractor after major refactors or when this date is >30 days old.
```

## Workflow

```
Progress:
- [ ] 1. Ensure Graphify graph exists if repo has code (see `custom-rules/graphify-rule.mdc`)
- [ ] 2. Gather local + cloud sources (list above)
- [ ] 3. Draft outline → shard list
- [ ] 4. Write full-indexing-*.md parts
- [ ] 5. Write manifest.md (read order + metadata)
- [ ] 6. Remove replaced shards
- [ ] 7. Kick off incremental Graphify sync on touched index files (`.cursor/scripts/graphify-update-changed.py`), or full `graphify update .` if no graph exists
```

## Quality bar

Each index must let a **cold-start agent** answer without broad search:

- What is this repo for?
- Directory layout and ownership
- How to build, test, run, deploy
- Cursor rules/skills that apply and when
- Architecture and critical dependencies
- Recent intentional decisions (from git + transcripts)
- Known gotchas and non-obvious conventions

Keep prose dense and factual. No filler. Link paths; avoid pasting large code blocks — cite paths and line ranges instead.

## Do not

- Index `node_modules/`, `.git/`, `graphify-out/` internals, caches, or secrets
- Commit credentials, tokens, or `.env` values
- Create index files outside `docs/indexing/`
- Rely on index alone for edits — verify against source before changing code
